## 1. 文書の目的

本書は、地球上および地球周辺で現在進行している自然現象・宇宙現象・人工衛星の活動を、一つの「惑星の鼓動」として可視化するWebアプリケーション **Earth Pulse** の設計を定義する。

本アプリは、防災情報を網羅的に提供する業務用ダッシュボードではなく、複数の公開データを統合し、地球を一つの活動体として感じられる視覚体験を提供することを主目的とする。

一方で、表示する情報については、出典・更新時刻・取得失敗を明示し、作品性と情報の誠実性を両立する。

---

## 2. プロダクト概要

### 2.1 一文定義

> 地球上と地球周辺で今起きている現象を、一つの「鼓動」として観察するリアルタイム・プラネタリウム。

### 2.2 中核価値

Earth Pulse の価値は、データ量の多さではなく、地震、自然災害、宇宙天気、人工衛星、昼夜の移動など、通常は別々に扱われる情報を、一つの惑星の活動として知覚できる点にある。

### 2.3 想定利用場面

- PCやタブレットで、現在の地球を静かに眺める
- 地震、火山、山火事、暴風雨などの発生地点を直感的に把握する
- ISSや主要衛星の位置を観察する
- 太陽風や地磁気活動を地球規模で感じる
- 展示、教育、デモ、スクリーンセーバー的表示に利用する

### 2.4 非目標

v0.1では、以下を目的としない。

- 災害時の避難判断や安全判断に利用する公式防災システム
- すべての自然現象を網羅するデータベース
- 個別地点の詳細な天気予報
- 航空機・船舶の完全なリアルタイム追跡
- ユーザーアカウントやクラウド同期
- 独自サーバーによる常時データ収集

## 3. 設計原則

### 3.1 体験を先に設計する

優先順位は以下とする。

1. 眺めていたくなる体験
2. 視覚的一貫性
3. データの信頼性と透明性
4. 操作のわかりやすさ
5. 機能数

### 3.2 情報を載せすぎない

すべての現象を常時強調表示せず、通常時は淡く存在させ、選択時または活動度が高い場合のみ強調する。

### 3.3 「リアルタイム」を誇張しない

データごとに更新頻度が異なるため、単に LIVE と表記せず、各データの取得時刻、経過時間、計算方式を表示する。

### 3.4 独自指標を公式指標に見せない

Earth Pulse が算出する `Planetary State` は、危険度や災害評価ではなく、複数データを統合した視覚演出上の活動状態とする。

### 3.5 API障害時にも壊れない

一部APIが取得できなくても、地球、自転、昼夜境界、ローカル計算、取得済みデータなどを用いてアプリを継続表示する。

## 5. 情報分類

画面上の情報は、API提供元ではなく、地球の活動系に基づいて分類する。

| 系 | UI表示名 | 主な情報 |
|---|---|---|
| 基礎状態 | CORE | 自転、昼夜境界、太陽直下点、UTC、月齢 |
| 地殻 | CRUST | 地震、震源、規模、深さ、火山イベント |
| 大気 | AIR | 気象、暴風雨、気圧、風、気温 |
| 地表 | SURFACE | 山火事、洪水、干ばつ、砂塵、海氷、氷山 |
| 宇宙天気 | SPACE | 太陽風、磁場、Kp指数、地磁気活動 |
| 軌道 | ORBIT | ISS、主要人工衛星、軌道 |

v0.1では AIR の詳細な全球気象可視化を対象外とし、NASA EONETに含まれる暴風雨イベント等を限定表示する。

## 6. 利用データ

### 6.1 USGS Earthquake API

用途:

- 世界の地震
- 発生時刻
- 緯度・経度
- 深さ
- マグニチュード
- 津波フラグ
- 公式詳細URL

取得方針:

- 原則として過去24時間のGeoJSONを取得する
- 画面表示件数は一定数に制限する
- 1〜5分間隔で再取得する
- 同一イベントIDは重複生成しない

### 6.2 NASA EONET v3

用途:

- 山火事
- 火山
- 暴風雨
- 洪水
- 干ばつ
- 砂塵
- 海氷・氷山等

取得方針:

- `status=open` を基本とする
- GeoJSONを優先利用する
- イベントカテゴリごとに表示スタイルを変える
- 更新頻度は15〜60分程度とする

### 6.3 NOAA Space Weather Prediction Center

用途:

- 太陽風速度
- 惑星間磁場
- Kp指数または地磁気活動
- 宇宙天気状態

取得方針:

- 小容量JSONを使用する
- 1〜5分間隔で取得する
- 取得値は `Planetary State` の算出に利用する

### 6.4 CelesTrak

用途:

- ISS等の軌道要素
- 主要人工衛星の軌道要素

取得方針:

- TLEまたは対応形式を取得する
- 位置は `satellite.js` 等を用いてブラウザ内で計算する
- 軌道要素は数時間単位で更新する
- 画面上の位置は毎秒更新する

### 6.5 ブラウザ内計算

APIなしで以下を算出する。

- 地球の自転角
- 昼夜境界
- 太陽直下点
- UTC
- 月齢または月相の簡易値
- 取得済みTLEからの衛星位置

### 7.2 地球儀

画面の主役とし、全画面に近い領域を占有する。

要件:

- ドラッグ操作による回転
- ホイール・ピンチによるズーム
- 自動回転のON/OFF
- 昼夜境界の表示
- 夜側の都市光または簡易発光表現
- イベントマーカーの表示
- 地球裏側のマーカーは適切に隠す
- 画面サイズに応じて自動リサイズする

### 7.3 ヘッダー

表示項目:

- `EARTH PULSE`
- UTC時刻
- 全体データ状態
- 設定ボタン
- サウンドボタンは将来拡張とする

### 7.4 レイヤーメニュー

画面左端に縦型で表示する。

```text
CORE
CRUST
AIR
SURFACE
SPACE
ORBIT
```

状態:

- ON: 通常表示
- FOCUS: 他レイヤーを暗くして選択レイヤーを強調
- OFF: 非表示

スマートフォンでは下部の横スクロールメニューに変更する。

### 7.5 Planetary State

画面左下または下中央に表示する。

例:

```text
PLANETARY STATE
RESTLESS
```

状態候補:

- QUIET
- BREATHING
- ACTIVE
- RESTLESS
- CHARGED
- STORMING

補足表示:

> 複数データを視覚的に統合した独自表現です。公式の危険度ではありません。

### 7.6 詳細カード

イベント選択時に表示する。

地震例:

```text
EARTHQUAKE
M 5.8
Depth 34 km
South Pacific Ocean
23 minutes ago
Source: USGS
```

共通項目:

- イベント種別
- 名称または場所
- 発生・更新時刻
- 主要値
- データ提供元
- 最終取得時刻
- 公式情報リンク

カード外クリックまたは閉じる操作で非表示にする。

### 7.7 データ状態表示

APIごとに以下の状態を持つ。

- `LOADING`
- `LIVE`
- `STALE`
- `LAST KNOWN DATA`
- `UNAVAILABLE`

全体表示では、最も悪い状態を単純採用せず、取得成功数と失敗数を要約する。

例:

```text
DATA 4/5 ONLINE
```

## 8. 表現仕様

### 8.1 地震

- 発生地点から同心円状の波紋を発生させる
- 新しいイベントほど明るく表示する
- マグニチュードに応じて波紋サイズを変える
- 深さに応じて透明度またはマーカー形状を変える
- 一定時間後に波紋は減衰し、マーカーのみ残す
- 大規模地震でも過度な点滅は避ける

### 8.2 火山

- 短い縦方向の発光または脈動で表現する
- 噴火映像のような誇張表現は行わない

### 8.3 山火事

- 小さな熾火のような明滅で表現する
- 広域イベントは淡い面または複数点で示す

### 8.4 暴風雨

- 渦または円形リングで抽象化する
- 進行方向情報がある場合のみ短い尾を表示する

### 8.5 宇宙天気

- 太陽方向から微細粒子を流す
- 太陽風速度に応じて粒子速度を変える
- 地磁気活動が高い場合、極域の発光を強める
- 値が取得できない場合、演出を通常状態に戻す

### 8.6 人工衛星

- 本体は小さな光点として表示する
- ISSは他衛星よりやや強調する
- 軌道線は選択時またはORBIT FOCUS時のみ表示する
- 地球裏側では自然に遮蔽する

## 9. Planetary State 算出仕様

### 9.1 目的

複数の地球活動データを、視覚演出上の一つの状態へ要約する。

### 9.2 注意事項

- 防災上の危険度ではない
- 異なる単位のデータを正規化して利用する
- 欠損データはゼロ扱いせず、利用可能な項目だけで再配分する
- 算出根拠を設定画面または情報画面で説明する

### 9.3 初期算出案

```text
Pulse Score =
  Seismic Activity × 0.30
+ Surface Events × 0.20
+ Atmospheric Events × 0.20
+ Space Weather × 0.30
```

各値は0〜100に正規化する。

#### Seismic Activity

- 過去24時間の地震数
- 最大マグニチュード
- マグニチュードに基づく重み付き合計

#### Surface Events

- EONETの活動中イベント数
- 火山・山火事・洪水等のカテゴリ別重み

#### Atmospheric Events

- EONETの暴風雨等の活動中イベント数
- 将来はOpen-Meteo等の風・気圧データを追加

#### Space Weather

- 太陽風速度
- Kp指数
- 磁場データ

### 9.4 状態区分案

| Score | State |
|---:|---|
| 0–19 | QUIET |
| 20–39 | BREATHING |
| 40–54 | ACTIVE |
| 55–69 | RESTLESS |
| 70–84 | CHARGED |
| 85–100 | STORMING |

閾値は実データ取得後に調整する。

## 10. 操作仕様

### 10.1 地球操作

- ドラッグ: 地球回転
- ホイール / ピンチ: ズーム
- マーカー選択: 詳細カード表示
- 背景選択: 詳細カードを閉じる
- ダブルクリックまたはダブルタップ: 選択地点へズーム

### 10.2 自動回転

- 初期状態ではゆっくり自動回転する
- ユーザー操作中は停止する
- 操作終了後、一定時間経過で再開する
- 設定から無効化できる

### 10.3 Focus モード

レイヤー名を再選択または長押しすると、そのレイヤーを強調する。

Focus中は:

- 対象レイヤーを通常輝度で表示
- 他レイヤーを低輝度表示
- 対象レイヤーの簡易統計を表示

### 10.4 Ambient モード

- UIを最小化する
- 地球と現象のみ表示する
- 画面操作またはEscで通常表示へ戻る
- v0.1ではボタンによる手動切替のみとする

## 11. 状態管理

アプリ全体の状態は一か所で管理する。

```javascript
const appState = {
  ui: {
    activeLayers: [],
    focusedLayer: null,
    selectedEventId: null,
    ambientMode: false,
    autoRotate: true
  },
  data: {
    earthquakes: [],
    eonetEvents: [],
    spaceWeather: {},
    satellites: []
  },
  sources: {
    usgs: { status: 'idle', updatedAt: null, error: null },
    eonet: { status: 'idle', updatedAt: null, error: null },
    swpc: { status: 'idle', updatedAt: null, error: null },
    celestrak: { status: 'idle', updatedAt: null, error: null }
  },
  planetaryState: {
    score: null,
    label: 'CALCULATING'
  }
};
```

データ取得モジュールは直接DOMを書き換えず、状態を更新し、描画側へ通知する。

## 12. データ取得・キャッシュ

### 12.1 基本方針

- `fetch()` を使用する
- タイムアウトを設定する
- リトライは最大1回とする
- 短時間の連続再試行を避ける
- APIごとに更新間隔を分ける

### 12.2 想定更新間隔

| データ | 更新間隔 |
|---|---:|
| USGS地震 | 2分 |
| NASA EONET | 30分 |
| NOAA SWPC | 2分 |
| CelesTrak TLE | 6時間 |
| 衛星画面位置 | 1秒 |
| UTC・昼夜境界 | 1秒〜1分 |

### 12.3 ローカルキャッシュ

`localStorage` または `IndexedDB` に以下を保存する。

- 最終成功データ
- 取得時刻
- ユーザー設定
- レイヤー表示状態

キャッシュ利用時は `LAST KNOWN DATA` と表示する。

### 12.4 タイムアウト

各リクエストは `AbortController` を使用し、10秒程度で中断する。

### 12.5 CORS・外部障害

CORSまたはAPI仕様変更により取得できない場合、対象レイヤーのみ停止し、アプリ全体は継続する。

## 13. エラー処理

### 13.1 エラー分類

- ネットワークエラー
- タイムアウト
- HTTPエラー
- JSON解析エラー
- データ形式不一致
- 軌道計算エラー
- WebGL非対応

### 13.2 表示方針

ユーザーには技術的な例外文字列を直接表示しない。

例:

```text
SPACE WEATHER DATA UNAVAILABLE
Last successful update: 18 min ago
```

開発者向け情報はコンソールに出力する。

### 13.3 WebGL非対応

WebGLが利用できない場合は、簡易2D地図またはエラーメッセージを表示する。v0.1では最低限、対応ブラウザ案内を表示する。

## 14. 技術構成

### 14.1 基本技術

- HTML5
- CSS3
- JavaScript ES Modules
- WebGL
- 3D地球ライブラリ
- `satellite.js`

### 14.2 3D地球ライブラリ候補

第一候補: `Globe.gl`

理由:

- Three.jsベース
- 地球儀へのポイント、リング、アーク表示が容易
- MVP開発が速い
- 静的HTMLで利用しやすい

代替候補:

- Three.js: 自由度は高いが実装量が増える
- CesiumJS: GIS機能は強いがEarth Pulseには重量級

v0.1では Globe.gl を採用し、将来、表現上の制約が顕在化した場合にThree.js直接実装を検討する。

### 14.3 ビルド方式

v0.1ではビルドツールを必須としない。

- ES Modulesを使用
- CDNまたはローカル配置したライブラリを読み込む
- GitHub Pagesでそのまま配信可能とする

ただし、CDN障害やバージョン固定の観点から、主要ライブラリのローカル配置も検討する。

## 17. 共通データモデル

外部APIの形式をそのまま描画側へ渡さず、共通イベント形式へ変換する。

```javascript
{
  id: 'source:event-id',
  source: 'USGS',
  category: 'earthquake',
  layer: 'CRUST',
  title: 'M 5.8 - South Pacific Ocean',
  latitude: -23.1,
  longitude: 171.4,
  altitude: 0,
  occurredAt: '2026-07-27T10:00:00Z',
  updatedAt: '2026-07-27T10:03:00Z',
  intensity: 0.72,
  metadata: {},
  sourceUrl: 'https://...'
}
```

`intensity` は描画用の0〜1正規化値とし、公式危険度とは区別する。

## 18. デザイン仕様

### 18.1 基調

- 宇宙背景は黒に近い濃色
- 地球は深い藍色
- UIは白〜淡灰色
- 発光色は現象ごとに限定使用
- 半透明カードは最小限
- 装飾線やHUD風枠を多用しない

### 18.2 タイポグラフィ

- 見出し・数値: 等幅または準等幅
- 地名・説明: 高可読性サンセリフ
- 極端に小さい文字を避ける
- 大文字英字は短いラベルに限定する

### 18.3 アニメーション

- 基本は低速・滑らか
- 点滅ではなく明滅・減衰を使う
- 画面全体を頻繁に揺らさない
- `prefers-reduced-motion` に対応する

### 18.4 アクセシビリティ

- 色だけで状態を伝えない
- キーボード操作を可能にする
- 詳細カードにARIA属性を付与する
- コントラストを確保する

## 20. 性能要件

### 20.1 目標

- 初回表示: 一般的な回線で5秒以内を目標
- 地球儀操作: 30fps以上を目標
- データ更新で操作を停止させない
- メモリ使用量の継続増加を防ぐ

### 20.2 描画負荷対策

- 表示イベント件数を制限する
- 地球裏側や極小マーカーの描画を削減する
- アニメーション対象を新規・主要イベントに限定する
- 低性能端末では粒子数を削減する
- 衛星数を段階的に減らす

### 20.3 表示件数初期値

- 地震: 最大200件
- EONET: 最大100件
- 衛星: 最大20機
- 同時波紋: 最大30件

## 25. 受入条件

### 25.1 基本表示

- ページを開くと3D地球が表示される
- 地球は自動回転し、操作できる
- 昼側と夜側が現在時刻に応じて変化する

### 25.2 地震

- 過去24時間の地震が表示される
- マーカー選択で規模、深さ、場所、時刻、出典を確認できる
- 新しい地震は波紋として視認できる

### 25.3 自然イベント

- EONETの活動中イベントが表示される
- カテゴリごとに識別できる
- 公式情報への参照先を確認できる

### 25.4 宇宙天気

- 太陽風等の現在値または直近値が表示される
- 取得時刻が確認できる
- 取得失敗時に誤ったLIVE表示をしない

### 25.5 ISS

- ISS位置がブラウザ内計算で継続更新される
- 取得した軌道要素の更新時刻が確認できる

### 25.6 Planetary State

- 利用可能データから状態が算出される
- 一部データ欠損時も算出可能である
- 公式危険度ではない旨が表示される

### 25.7 障害耐性

- 一つのAPIが失敗しても地球儀と他レイヤーは動作する
- キャッシュがある場合は最終データとして表示する
- エラーが無限再試行を起こさない

### 25.8 レスポンシブ

- デスクトップで主要UIが重ならない
- スマートフォンで地球操作と詳細閲覧が可能である

## 29. 完成像

Earth Pulse v0.1は、機能の多さではなく、ページを開いた瞬間に「地球が今も活動している」と感じられることを完成条件とする。

最終的な評価基準は、次の問いに集約する。

> 操作しなくても、30秒以上眺めていたくなるか。

この条件を満たしたうえで、データの出典、鮮度、取得失敗を誠実に示し、静的HTMLだけで成立する小さく強い作品として実装する。
