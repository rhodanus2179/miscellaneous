# Yomu Pace v0.1.0 要件定義書（静的構成版）

- 対象プロダクト: `Yomu Pace`（仮称）
- 対象版: v0.1.0
- リポジトリ: `rhodanus2179/miscellaneous`
- 配置先: `yomu-pace/`
- 公開方式: GitHub Pagesからの静的配信
- 実装方式: ビルド不要のHTML / CSS / JavaScript
- 対応入力: 文章貼り付け、TXT、Markdown
- 対象外: EPUB、PDF、URL本文取得、OCR
- データ処理: 端末内完結
- AI利用: 外部LLM API、Gemini Nano、生成AIを使用しない
- 日本語解析: BudouX＋決定論的な規則ベース処理
- 作成日: 2026-08-04
- 状態: 旧要件定義書を置き換える再設計案

---

## 1. 文書の目的

本書は、日本語文章を意味のまとまりで提示し、利用者が前後関係を失わず一定のテンポで通読できる読書支援アプリ `Yomu Pace` の要求事項を定義する。

本再設計では、利用者と開発者の双方にとって扱いやすいことを優先し、次を固定条件とする。

1. 本番公開にビルドを必要としない
2. `main` ブランチへ静的ファイルを配置すればGitHub Pagesから利用できる
3. iPhoneを含む利用端末側にローカルサーバーや開発環境を要求しない
4. EPUB対応は初期版から除外する
5. 外部APIやクラウド保存を使用しない
6. 文章の理解を犠牲にした最高速度競争を行わない

---

## 2. 背景

既存のRSVP型速読アプリには、文章を一語または短い単位で中央に連続表示するものがある。しかし、日本語には空白による明示的な単語境界がなく、単純な文字数分割では助詞、固有名詞、数値・単位、法令名などを不自然に切りやすい。

また、一度表示した文字が消える方式では、通常の読書で行われる読み戻しが難しくなる。このためYomu Paceでは、中央表示だけでなく、前後チャンク表示と本文ハイライトを提供し、読み戻しを常に可能にする。

旧設計ではTypeScript、Vite、npm依存、Web Worker、EPUB解析を含めたが、初期版の本質に対して構成が重かった。本再設計では、読書体験に直接必要な機能だけを残す。

---

## 3. プロダクト定義

Yomu Paceは、貼り付けた日本語文章またはローカルのTXT・Markdownファイルを端末内で解析し、意味のまとまりに近いチャンクとして一定のペースで表示するローカルファーストの読書支援アプリである。

### 3.1 主な利用場面

- Web記事本文をコピーして貼り付け、集中して通読する
- TXT形式の文章を一定のテンポで読む
- Markdown形式の原稿、報告書、メモを読む
- 長文で行を見失いやすいときに、現在位置を強調して読む
- 既読文章を再読し、概要を確認する

### 3.2 対象利用者

- 日本語の長文を読む一般利用者
- 読書中の注意の逸れや行の見失いを減らしたい利用者
- 読書速度を自分で調整したい利用者
- 文章を外部サービスへ送信したくない利用者
- PCとiPhoneの両方で同じアプリを手軽に試したい利用者

### 3.3 対象外

- 読字障害、ADHD、視覚障害等の診断・治療
- 読解力の医学的・教育学的評価
- 超高速読書能力の獲得保証
- 文章の要約、書換え、翻訳
- 自動生成された理解度テスト
- クラウド同期、アカウント、共同利用
- DRM解除

---

## 4. 固定方針

### 4.1 ビルド不要

本番配信物は、リポジトリに保存されたHTML、CSS、JavaScript、画像、manifest、Service Worker等そのものとする。

- Vite、Webpack、Rollup等を本番公開に使用しない
- TypeScriptを本番コードとして使用しない
- `dist/`を生成しない
- GitHub Pagesがリポジトリ内のファイルをそのまま配信する
- ソースと公開物を一致させる

### 4.2 GitHub Pages直配信

mainへマージ後、次のようなHTTPS URLから直接利用できることを必須とする。

```text
https://rhodanus2179.github.io/miscellaneous/yomu-pace/
```

利用者側にnpm、Node.js、ローカルサーバー、PCのIPアドレス確認等を要求しない。

### 4.3 file直開きは対象外

`file://`で`index.html`を直接開く方式は必須としない。JavaScript Modules、Service Worker、PWA等はHTTP/HTTPS配信を前提とする。

### 4.4 ローカルファースト

- 本文、読書位置、設定、履歴を外部送信しない
- アクセス解析を初期版では導入しない
- CDNを実行時に利用しない
- 外部フォントを必須としない

### 4.5 原文尊重

- 原文の文字列、段落順、見出し順を変更しない
- チャンク化は表示方法であり、本文の書換えではない
- 正規化前の原文を保存する
- チャンクには原文上の位置を保持する

## 6. 入力要件

### 6.1 文章貼り付け

利用者は本文を貼り付けて新規文書を登録できる。

任意項目:

- タイトル
- 著者または出典
- 入力形式: プレーンテキスト / Markdown

タイトル未入力時は次の順で仮タイトルを生成する。

1. 最初のMarkdown見出し
2. 最初の非空行の先頭40文字
3. 取込み日時

### 6.2 TXT

必須対応:

- UTF-8 BOMなし
- UTF-8 BOMあり

可能な範囲で対応:

- UTF-16LE BOMあり
- UTF-16BE BOMあり

Shift_JISの推測読込みは初期版では行わない。文字化けした内容を自動保存しない。

### 6.3 Markdown

初期版が解釈する構造:

- ATX見出し `#`〜`######`
- 段落
- 箇条書き
- 番号付きリスト
- 引用
- 水平線
- fenced code block
- 単純な表
- リンクの表示文字列
- インラインコード

方針:

- MarkdownをHTMLとして描画しない
- raw HTMLを実行・解釈しない
- raw HTMLは通常文字列として扱うか、設定により除外する
- コードブロックと表は非散文として自動再生を停止する
- 対応外記法があっても取込み全体を失敗させない

### 6.4 上限

初期値:

- 貼り付け本文: 2,000,000文字
- TXT / Markdown: 10 MB
- 抽出本文: 2,000,000文字

上限超過時は保存せず、理由を表示する。

## 7. 日本語チャンク生成要件

### 7.1 処理方針

1. 原文を保存
2. 解析用テキストを正規化
3. 文書をブロックへ分割
4. 文境界を検出
5. URL等の保護範囲を検出
6. BudouXからフレーズ境界候補を取得
7. 独自ルールで候補を評価
8. 文全体を見てチャンク列を決定
9. 表示時間を計算
10. 原文との対応を検証

### 7.2 チャンク長プリセット

| 設定 | 目標 | 通常範囲 | 原則上限 |
|---|---:|---:|---:|
| 短め | 11文字 | 6〜16文字 | 24文字 |
| 標準 | 16文字 | 8〜24文字 | 32文字 |
| 長め | 23文字 | 12〜32文字 | 44文字 |

見出し、短文、保護対象は例外を認める。

### 7.3 分割保護対象

- URL
- メールアドレス
- 日付・時刻・期間
- 数値と単位
- 法令条項
- 英字略称・製品番号
- インラインコード
- 括弧の開始記号だけ、終了記号だけ
- 句読点だけ

### 7.4 避ける分割

- 助詞・助動詞だけの短片
- 閉じ括弧や句読点から始まるチャンク
- 開き括弧で終わるチャンク
- URL内の`?`や`!`を文末と誤認する分割
- 数字と直後の単位の分離

### 7.5 決定論

同じ本文、同じ設定、同じ`chunkingVersion`からは、同じチャンク列を生成する。

### 7.6 原文追跡

各チャンクは次を保持する。

```js
{
  id,
  text,
  sourceStart,
  sourceEnd,
  blockId,
  sentenceId,
  kind,
  pauseClass,
  durationMsAtBaseRate,
  flags
}
```

チャンクを順に連結すると、解析用本文と一致することを必須とする。

## 8. 表示モード

### 8.1 コンテキストモード

既定モードとする。

- 前のチャンク
- 現在チャンク
- 次のチャンク

を同時に表示し、現在チャンクを最も強く示す。

### 8.2 ハイライトモード

- 現在の段落またはブロックを表示する
- 現在チャンクだけを強調する
- 自動再生中も前後の本文を確認できる
- 読み戻しや任意位置への移動を容易にする

### 8.3 フォーカスモード

- 現在チャンクだけを中央に大きく表示する
- 画面左右の操作で前後へ移動できる
- 初回利用時に前後文脈が見えないことを案内する

モード切替時は読書位置を維持する。

## 9. 再生・操作要件

必須操作:

- 再生
- 一時停止
- 前のチャンク
- 次のチャンク
- 前の文
- 次の文
- 前の段落
- 次の段落
- 文書先頭
- 文書末尾

キーボード:

| 操作 | キー |
|---|---|
| 再生・停止 | Space |
| 前後チャンク | ← / → |
| 前後文 | Shift＋← / → |
| 速度変更 | ↓ / ↑ |
| 全画面 | F |
| 閉じる | Esc |

タッチ:

- 中央タップ: 再生・停止
- 左側タップ: 前のチャンク
- 右側タップ: 次のチャンク
- 左右スワイプ: 文単位移動（設定で無効化可能）

ブラウザタブが非表示になった場合は自動停止し、復帰時に勝手に再開しない。

## 10. 表示時間

主な速度単位は「文字/分」とする。

- 設定範囲: 200〜2,000文字/分
- 初期値: 600文字/分
- 調整単位: 25文字/分

基本式:

```text
基本表示時間 = 表示文字数 ÷ 設定文字/分 × 60,000
最終表示時間 = 基本表示時間 × 内容補正 + 休止時間
```

補正対象:

- 数字・単位
- 英字列
- 漢字・英字・数字の混在
- 括弧・引用
- 見出し
- URL
- fallback分割

休止対象:

- 読点
- 文末
- 段落末
- 見出し・セクション末

短いチャンクが瞬間的に消えないよう最低表示時間を設ける。

## 11. 保存要件

IndexedDBへ次を保存する。

- 文書メタデータ
- 原文
- 解析用本文
- ブロック
- チャンク
- 読書位置
- 表示設定
- 読書セッション履歴

ライブラリ表示時に全本文を読み込まないよう、メタデータと本文・チャンクを分離する。

文書削除時は確認を行う。初期版ではごみ箱や復元機能を設けない。

## 12. 性能要件

### 12.1 基本方針

初期版ではWeb Workerを使わず、処理を文・ブロック単位に分割し、定期的にブラウザへ制御を返す。

- 解析進捗を表示する
- 解析をキャンセルできる
- 連続して長時間メインスレッドを占有しない
- 画面が固まったように見せない

### 12.2 目標

- 10万文字のTXTを一般的な近年のスマートフォンで実用的な時間内に処理する
- 解析中もキャンセルボタンが反応する
- 読書中のチャンク切替で目立つフレーム落ちを生じさせない

性能不足が実機で確認された場合のみ、Web Workerを将来追加する。

- PCとスマートフォンの双方で利用できる

## 15. セキュリティ・プライバシー

- 文章本文を外部へ送信しない
- CDNから実行時コードを読み込まない
- raw HTMLを実行しない
- 本文表示に`innerHTML`を使わない
- 画面表示はText Nodeまたは`textContent`を使用する
- エラーログに本文を含めない
- 外部リンクは自動で開かない
- Service Workerの対象範囲を`yomu-pace/`配下に限定する
- Content Security Policyを設定する

BudouXはリポジトリ内へ同梱し、ライセンス文書を保持する。

## 17. 受入基準

### 17.1 配信

- npm installやビルドをせず公開できる
- mainの`yomu-pace/`がそのまま配信物である
- PC ChromeとiPhone Safariから同じHTTPS URLで起動できる

### 17.2 取込み

- 貼り付け文章を保存し、再起動後も開ける
- UTF-8 TXTの段落順を保持する
- Markdownの見出し、段落、リスト順を保持する
- raw HTMLを実行しない
- 失敗した取込みが壊れた文書を残さない

### 17.3 チャンク

- チャンク連結結果が解析用本文と一致する
- 句読点だけのチャンクを作らない
- URLを途中で分割しない
- URL内の`?`を文末として分割しない
- 数字と単位を原則として分離しない
- 助詞だけの短片を原則として作らない
- 同じ条件で同じ結果を生成する

### 17.4 読書

- 3モードを位置を失わず切り替えられる
- 1操作で自動再生を停止できる
- 1操作で直前チャンクへ戻れる
- 文末後は通常より長く表示される
- タブを離れると停止する
- 再起動後に読書位置が復元される

### 17.5 プライバシー

- 本文を送信するネットワークリクエストがない
- 外部LLM API、Gemini Nano、kuromoji.jsを含まない
- 実行時CDN依存がない
