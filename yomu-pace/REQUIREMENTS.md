# Yomu Pace 要件定義書

- 文書名: Yomu Pace 要件定義書
- 対象プロダクト: `Yomu Pace`（仮称）
- 初期目標版: v0.1.0
- リポジトリ: `rhodanus2179/miscellaneous`
- 配置先: `yomu-pace/`
- 実装方式: 静的Webアプリ / PWA
- 配信候補: GitHub Pages
- データ処理: 端末内完結
- AI利用: 外部LLM API、Gemini Nano、生成AIを使用しない
- 日本語解析: BudouXおよび規則ベース処理。kuromoji.jsは使用しない
- 作成日: 2026-08-04

---

## 1. 文書の目的

本書は、日本語文章を意味のまとまりに分割し、利用者が無理なく一定のテンポで読み進められる読書支援アプリ `Yomu Pace` の要求事項を定義する。

本アプリは、表示速度だけを高める「速読訓練アプリ」を目標としない。通常の読書で行われる読み戻しや文章構造の把握を維持しつつ、視線移動、行の見失い、注意の逸れを減らすことを目指す。

初期版では、文章の貼り付け、TXT、Markdown、EPUBを対象とする。PDF取込みは将来拡張とする。

---

## 2. 背景と課題

既存のRSVP型速読アプリには、文章を一語または短い単位で中央に連続表示するものがある。一方、日本語では空白による単語境界がなく、単純な文字数分割や単語分割では、助詞、固有名詞、数値・単位、文節などが不自然に分断されやすい。

また、純粋なRSVPでは直前の文章が消えるため、通常の読書で理解を補う読み戻しが難しくなる。現代的な速読アプリが読解を必ずしも改善しないことや、読み戻しが再読に利用されることが報告されている。

一方、日本語では文節を分断しないレイアウトが読みの効率を改善し得ることが実験的に示されている。このため、本アプリは次の方針を採用する。

1. 日本語の意味のまとまりを優先して区切る
2. 一度表示した文章を容易に読み戻せるようにする
3. 一定間隔ではなく、文字数・句読点・記号等に応じて提示時間を調整する
4. 読書速度と理解度を同一視しない
5. 原文を変更せず、分割と表示だけを支援する

---

## 3. プロダクトの位置付け

### 3.1 プロダクト定義

Yomu Paceは、長文を日本語向けのチャンクに分割し、利用者が一定のリズムで読めるように表示する、ローカルファーストの読書支援アプリである。

### 3.2 主要な利用場面

- ニュース記事や解説記事を貼り付けて通読する
- TXT形式の長文を読む
- Markdown形式の報告書、原稿、メモを読む
- DRMのないEPUB書籍を章ごとに読む
- 行を見失いやすい長文を一定のペースで読む
- 既読文章を再読し、概要を短時間で確認する

### 3.3 対象利用者

- 日本語の長文を読む一般利用者
- 集中の維持や行追跡を補助したい利用者
- 通読速度を調整しながら読みたい利用者
- 読書データを外部サービスへ送信したくない利用者

### 3.4 対象外

初期版は次を目的としない。

- 読字障害、ADHD、視覚障害等の診断・治療
- 読解力の医学的・教育学的評価
- 超高速読書能力の獲得保証
- 文章の要約、書換え、翻訳
- 自動生成された理解度テスト
- クラウド同期、アカウント、共同利用
- DRM付きEPUBの解除または取込み

## 4. 設計原則

### 4.1 理解優先

表示速度は利用者が調整できるが、アプリは「速いほど優れている」と表現しない。速度の増加を読解力向上として扱わない。

### 4.2 読み戻しを妨げない

すべての自動再生モードで、1操作で直前のチャンクへ戻れることを必須とする。純粋な中央表示モードでも、履歴を失わない。

### 4.3 原文尊重

原文の文字列、段落順、見出し順、章順を変更しない。正規化は表示・解析用の内部コピーに対して行い、原文を保持する。

### 4.4 日本語最適化

日本語の分割は、BudouXによるフレーズ境界候補と、句読点・記号・長さ・特殊表現を扱う規則ベース処理を組み合わせる。

kuromoji.js、外部LLM API、Gemini Nanoは使用しない。

### 4.5 ローカルファースト

取込み文章、読書位置、設定、読書履歴は端末内に保存する。利用者の文章を外部サーバーへ送信しない。

### 4.6 説明可能性

チャンク分割と表示時間は決定論的な規則で算出する。同じ設定と同じ文章からは、原則として同じ結果を得る。

## 6. 機能要件

## 6.1 F-01 文章の貼り付け

利用者は入力欄へ日本語文章を貼り付け、新規文書として登録できる。

必須入力:

- 本文

任意入力:

- タイトル
- 著者または出典

タイトルが未入力の場合は、次の順で仮タイトルを生成する。

1. 最初のMarkdown見出し
2. 最初の空行までの先頭40文字
3. 取込み日時

受入条件:

- 1文字以上の本文を登録できる
- 空白のみの本文は登録できない
- 登録前に文字数を表示する
- 登録後にチャンク生成結果の概要を表示する

## 6.2 F-02 TXT取込み

利用者は `.txt` ファイルを選択して登録できる。

対応文字コード:

- UTF-8（BOMあり・なし）を必須
- UTF-16LE / UTF-16BEは可能な範囲で対応
- Shift_JIS自動判定はv0.1.0では必須としない

受入条件:

- UTF-8 TXTを正常に読み込める
- 改行と段落境界を保持する
- 読込み不能な場合は、データを保存せず理由を表示する
- ファイル内容を外部へ送信しない

## 6.3 F-03 Markdown取込み

利用者は `.md` または `.markdown` ファイルを登録できる。

対象構造:

- 見出し
- 段落
- 箇条書き・番号付きリスト
- 引用
- 水平線
- コードブロック
- 表
- リンク

読書用テキストへの変換方針:

- 見出し、段落、リスト項目、引用の順序を保持する
- Markdown記号は原則として読み上げ対象から除外する
- リンクは表示文字列を使用する
- URLだけのリンクはURLを一つの特殊チャンクとして扱う
- コードブロックと表は「非散文ブロック」として自動再生を停止し、固定表示する
- 利用者は非散文ブロックを読む、またはスキップできる

受入条件:

- 主要構造の順序が変わらない
- コードや表が細切れに自動再生されない
- HTMLを含むMarkdownは、スクリプトを実行しない

## 6.4 F-04 EPUB取込み

利用者はDRMのない `.epub` ファイルを登録できる。

初期版の要件:

- EPUB 2およびEPUB 3の一般的なリフロー型文書を対象とする
- spine順に章・節の本文を抽出する
- 目次が取得できる場合は章移動に使用する
- 固定レイアウトEPUBは対象外として警告する
- JavaScript等の埋込みスクリプトは実行しない
- 画像、音声、動画は本文抽出時に無視する
- `ruby` は親文字を本文として保持し、`rt` は初期設定では除外する
- DRM付きまたは暗号化された本文は読み込まない

受入条件:

- 章順がEPUBのspine順と一致する
- 見出しと段落境界を保持する
- 章単位で読書位置を保存する
- 取込み失敗時に既存データを壊さない

## 6.5 F-05 日本語向けチャンク生成

### 6.5.1 処理順序

1. 原文保存
2. 改行・Unicode・不可視文字の正規化
3. 文書ブロック分割
4. 文境界候補の検出
5. 特殊表現の保護
6. BudouXによるフレーズ境界候補の取得
7. 短すぎる候補の結合
8. 長すぎる候補の再分割
9. 句読点・段落情報の付与
10. 表示時間の算出

### 6.5.2 既定のチャンク長

- 目標範囲: 10〜24文字
- 推奨中心値: 16文字前後
- 原則上限: 32文字
- 文法・固有表現の保護を優先する場合は上限超過を許容する
- 最小長を固定せず、見出し、短文、会話文は短いまま保持できる

利用者は「短め・標準・長め」の3段階を選択できる。

### 6.5.3 分割禁止または結合優先の対象

- 数字と単位: `10 t/日`、`20m³`、`95％`
- 日付・時刻: `2026年8月4日`、`19:00〜21:00`
- 法令・条項: `廃棄物処理法第6条`
- 製品名・組織名・英字略称の連続
- URL、メールアドレス
- 括弧の開始記号だけ、終了記号だけ
- 句読点だけ
- 助詞・助動詞だけの短い断片
- Markdownのインラインコード

### 6.5.4 原文追跡

各チャンクは、原文上の開始位置と終了位置を保持する。

```ts
interface ReadingChunk {
  id: string;
  text: string;
  sourceStart: number;
  sourceEnd: number;
  blockId: string;
  sentenceId: string;
  kind: 'prose' | 'heading' | 'list' | 'quote' | 'code' | 'table' | 'url';
  pauseClass: 'none' | 'comma' | 'sentence' | 'paragraph' | 'section';
  durationMs: number;
}
```

原文位置の保持は、読み戻し、進捗保存、チャンク品質確認、将来のPDFページ対応に使用する。

## 6.6 F-06 読書表示モード

### A. コンテキストモード（既定）

- 現在のチャンクを中央で強調する
- 直前と次のチャンクを薄く表示する
- 同じ段落内の位置が分かる
- 1操作で直前へ戻れる

### B. ハイライトモード

- 段落または数行の本文を残す
- 現在のチャンクだけを強調する
- 読了済み箇所は弱く表示する
- 前後関係を最も保持しやすいモードとする

### C. フォーカスモード

- 現在のチャンクだけを大きく表示する
- Instapaper等のSpeed Readingに近い体験を提供する
- 画面タップまたはキー操作で直前のチャンクを即時再表示できる
- 初回利用時に、前後文脈が見えないモードであることを案内する

表示モードは読書中でも切り替え可能とし、位置を維持する。

## 6.7 F-07 再生・移動操作

必須操作:

- 再生
- 一時停止
- 直前のチャンク
- 次のチャンク
- 直前の文
- 次の文
- 直前の段落
- 次の段落
- 章移動（EPUB）
- 文書先頭・末尾移動

キーボード既定:

| 操作 | キー |
|---|---|
| 再生・停止 | Space |
| 前のチャンク | ← |
| 次のチャンク | → |
| 前の文 | Shift + ← |
| 次の文 | Shift + → |
| 速度を下げる | ↓ |
| 速度を上げる | ↑ |
| 全画面切替 | F |
| 終了・設定を閉じる | Esc |

タッチ操作:

- 画面中央タップ: 再生・停止
- 左側タップ: 前のチャンク
- 右側タップ: 次のチャンク
- 左右スワイプ: 文単位の移動

誤操作防止のため、スワイプは設定で無効化できる。

## 6.8 F-08 可変表示時間

### 6.8.1 速度単位

日本語では単語数が安定しないため、主表示は「文字/分」とする。

- 設定範囲: 200〜2,000文字/分
- 初期値: 600文字/分
- 微調整: 25文字/分単位
- プリセット: ゆっくり、標準、速め、カスタム

初期値は能力の基準ではなく、容易に変更できる製品上の既定値とする。

### 6.8.2 基本計算

```text
基本表示時間 = チャンク文字数 ÷ 設定文字/分 × 60,000
最終表示時間 = 基本表示時間 × 内容補正 + 休止時間
```

### 6.8.3 内容補正

初期版では次を決定論的に扱う。

- 漢字・英字・数字の混在
- 数値と単位
- URL
- 括弧・引用
- 長い英字略称
- チャンク長
- 見出し

補正係数は設定ファイルで管理し、テスト可能にする。

### 6.8.4 休止時間

- 読点・中点等: 短い休止
- 句点・疑問符・感嘆符: 中程度の休止
- 段落末: 長い休止
- 見出し・章末: より長い休止

利用者は「句読点で間を取る」の強さを3段階で設定できる。

### 6.8.5 最低・最大表示時間

- 短いチャンクが瞬間的に消えないよう、最低表示時間を設ける
- 長大チャンクが過度に残らないよう、最大表示時間を設ける
- 上限に達した場合も、利用者は手動で停止・戻ることができる

## 6.9 F-09 保存

保存先はIndexedDBを基本とする。

保存対象:

- 文書メタデータ
- 原文
- 抽出済み本文
- チャンク情報
- EPUB章情報
- 現在位置
- 表示モード
- 速度設定
- 文字サイズ、行間、テーマ
- 読書セッション履歴

保存しないもの:

- 外部サーバー上のアカウント情報
- 端末固有識別子
- 広告識別子

## 6.10 F-10 文書ライブラリ

一覧に表示する情報:

- タイトル
- 種別: 貼付け / TXT / Markdown / EPUB
- 進捗率
- 最終読書日時
- 文字数
- EPUBの場合は現在章

操作:

- 読書を再開
- 詳細表示
- タイトル・著者編集
- 再チャンク化
- 原文表示
- 削除

削除は確認後に行う。削除した文書は初期版では復元できないことを明示する。

## 6.11 F-11 進捗と実測情報

読書画面に次を表示できる。

- 文書全体の進捗率
- 現在の章・節
- 現在チャンク番号 / 総チャンク数
- 設定文字/分
- 実測経過時間
- 実測文字/分
- 推定残り時間

実測文字/分は、一時停止中の時間を除外した値と、総経過時間を含む値を区別する。

「実測文字/分」は理解度や能力の指標ではないことを明記する。

## 6.12 F-12 オフライン動作

初回読込み後、次をオフラインで利用できる。

- 保存済み文書の閲覧
- 新規の貼り付け
- TXT、Markdown、EPUBのローカル取込み
- チャンク生成
- 読書位置保存
- 設定変更

CDN必須の構成にしない。BudouX、EPUB処理ライブラリ等は配信物に同梱する。

## 6.13 F-13 操作性・アクセシビリティ

- スマートフォンとPCの双方で利用できる
- 主要操作はキーボードだけで行える
- タップ領域は十分な大きさを確保する
- 文字サイズ、行間、表示幅を変更できる
- ライト、ダーク、端末設定連動を提供する
- `prefers-reduced-motion` を尊重する
- 色だけで現在位置や状態を示さない
- フォーカスリングを消さない
- 自動再生中の頻繁なARIA live更新は行わない
- スクリーンリーダー利用時は通常本文表示へ切り替えられる

## 6.14 F-14 チャンク品質確認

設定内の詳細機能として、チャンク一覧を確認できる。

表示内容:

- チャンク境界
- 文字数
- 表示時間
- 休止種別
- 原文位置

利用者は、現在文書について境界を手動調整できることが望ましい。ただし、v0.1.0では「境界の確認」と「問題箇所のコピー」をMustとし、永続的な手動編集はShouldとする。

問題報告用に、原文全体ではなく対象前後だけをクリップボードへコピーできる。

## 6.15 F-15 読書セッション履歴

記録項目:

- 文書ID
- 開始・終了日時
- 開始位置・終了位置
- 読了文字数
- 再生時間
- 総経過時間
- 戻る操作回数
- 一時停止回数
- 平均設定速度
- 使用モード

履歴は端末内に保存し、利用者が全削除できる。

戻る操作回数や停止回数を「失敗」と評価しない。

## 7. 非機能要件

## 7.1 プライバシー

- 文章本文を外部へ送信しない
- アクセス解析は初期版では導入しない
- エラーログに文章本文を含めない
- 外部フォントを必須としない
- 外部LLM API、Gemini Nano、クラウド解析を使用しない

## 7.2 セキュリティ

- EPUBおよびMarkdown内のスクリプトを実行しない
- HTMLは安全な要素・属性だけを扱う
- `innerHTML` へ未検証文字列を直接挿入しない
- EPUB内の外部リソースを自動取得しない
- CSPを設定する
- ファイルの拡張子だけでなく内容も検証する
- 異常に大きいファイルや展開後サイズを制限し、ZIP bombを防ぐ

## 7.3 ファイル上限

初期値:

- 貼り付け本文: 2,000,000文字
- TXT / Markdown: 10 MB
- EPUB: 100 MB
- EPUB展開後総量: 300 MB
- 抽出本文: 10,000,000文字

上限値は定数化し、端末事情に応じて見直せるようにする。

## 7.4 性能

目標:

- 10万文字のTXTまたはMarkdownを、一般的な近年のスマートフォンで5秒以内にチャンク化する
- 100万文字では進捗表示を行い、UIを長時間ブロックしない
- 解析は必要に応じてWeb Workerで実行する
- 読書中のチャンク切替で目立つフレーム落ちを生じさせない
- 文書一覧表示時に全本文をメモリへ展開しない

性能目標は実機テストで検証し、端末差が大きい場合は基準を改訂する。

## 7.5 対応環境

初期対象:

- iOS / iPadOS Safariの現行および1世代前
- Android Chromeの現行および1世代前
- Windows 11 Chrome / Edgeの現行および1世代前
- macOS Safari / Chromeの現行および1世代前

必須APIがない場合は、機能単位で明確に案内する。

## 7.6 信頼性

- ファイル取込み途中で失敗しても、既存文書を壊さない
- 原文保存後にチャンク生成が失敗した場合、再試行できる
- アプリ更新後も既存データを読み込める
- IndexedDBスキーマにはバージョンを付与する
- 保存処理失敗時に、保存済みと誤認させない

## 7.7 保守性

- TypeScriptを採用する
- 分割、時間計算、ファイル抽出、保存、UIを分離する
- チャンク処理は純粋関数を中心に実装する
- 主要規則に単体テストを設ける
- 外部依存を最小限にする
- ライブラリのライセンスを一覧化する

## 12. 受入基準

### 12.1 取込み

- 日本語の貼付け文章を登録し、再起動後も開ける
- UTF-8 TXTの段落順を保持できる
- Markdownの見出し・段落・リスト順を保持できる
- 一般的なDRMなしEPUBをspine順に抽出できる
- 失敗した取込みがライブラリに壊れた文書を残さない

### 12.2 チャンク

- 句読点だけのチャンクを生成しない
- URLを途中で分割しない
- 数字と直後の単位を原則として分割しない
- 開き括弧または閉じ括弧だけのチャンクを原則として生成しない
- 助詞だけの短いチャンクを原則として生成しない
- 原文を連結すると、正規化で明示的に除外した文字を除き元本文と一致する
- 同じ設定では同じチャンク列を生成する

### 12.3 読書

- 3モードを位置を失わず切り替えられる
- 自動再生中に1操作で停止できる
- 1操作で直前のチャンクへ戻れる
- 句点後が通常チャンクより長く表示される
- 読書位置が再起動後に復元される
- 速度変更が次チャンクから反映される

### 12.4 プライバシー・オフライン

- 開発者ツールで、本文を送信するネットワークリクエストがない
- 初回キャッシュ後はオフラインで保存済み文書を読める
- オフラインでTXT、Markdown、EPUBを取り込める
- 外部LLM API、Gemini Nano、kuromoji.jsを含まない

### 12.5 アクセシビリティ

- キーボードのみで主要機能を操作できる
- 200％ズームで主要操作が欠落しない
- `prefers-reduced-motion` で不要なアニメーションを抑制する
- ダークモードでも十分なコントラストを確保する

## 15. 成功条件

v0.1.0の成功は、次で判断する。

1. 日本語文章が不自然に細切れになりにくい
2. 利用者が前後関係を見失わずに一定のテンポで読める
3. 読み戻しが即座に行える
4. TXT、Markdown、EPUBを端末内だけで安定して処理できる
5. 速度を上げることを強制せず、利用者が自分に合う表示を選べる
6. 既存の日本語RSVPアプリより、数値・単位・括弧・固有表現の分割品質が高い
7. 文書内容が外部へ送信されない

初期評価では、単なる最高速度ではなく、次を確認する。

- 主観的な読みやすさ
- 内容を追えている感覚
- 読み戻しや停止のしやすさ
- 目の疲れ
- チャンク境界の違和感
- 通常表示と比べて継続して使いたいか
